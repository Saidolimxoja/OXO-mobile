# «Ҳудуд назорати» (Hudud Nazorati) — мобильное приложение OXO (Android)

Отметка прихода для «Давомат» и трек в рабочее время — у всех; отчёты о работах для
«Ишлар ҳисоботи» — только у сотрудников туманов (вилоят и республика видят только Давомат,
решает сервер: `canReportWork` в `/mobile/me`).
Сервер — бэкенд OXO, API `/api/mobile/*`; вход той же учётной записью OXO
(у пользователя должна быть включена «Мобил илова» и привязан сотрудник).

## Что умеет

- Вход, автообновление токена, выход.
- Бош саҳифа: сотрудник и рабочий день (праздники с сервера), Давомат, состояние трека;
  у туманов ещё норма за день/неделю/месяц, «Иш қўшиш» и сегодняшние работы.
- Новая работа (туманы): на выезде (с местом по GPS и адресом) или удалённо (телефон/AnyDesk),
  вид работы, организация, что сделано, номер обращения, заявитель, время, 1–4 фото.
- Ишларим (туманы): работы за любой день за 90 дней, детали и фото; сегодняшние можно удалить.
- Трек: точки GPS и сигнал «на связи» раз в минуту строго 09:00–18:00 рабочего дня
  (праздники с сервера), отправка раз в 2 минуты, без интернета копится на телефоне.
  GPS — foreground-сервис с постоянным уведомлением. Android запускает его только из открытого
  приложения, поэтому он включается при входе или возврате в приложение (утром — «Келдим»;
  точки до 09:00 не пишутся) и сам выключается в 18:00 и в нерабочий день.
- Давомат: «Келдим» — камера с овалом, место по GPS ищется параллельно. Снимок делается сам,
  когда в овале одно лицо, оно смотрит прямо, человек **моргнул** (фото не моргает) и точка
  GPS годится: у офиса, точная, не подменённая. Если распознавание на телефоне не заработало
  за 12 с, появляется запасная кнопка снимка, автомат продолжает работать. Сервер сверяет лицо
  с фото из анкеты и записывает, как сделан снимок (`auto`/`manual`), версию и телефон.
  Если «Келдим» сегодня ещё нужен, камера открывается сама при входе и при возврате в
  приложение. Ухода нет: выходы из офиса, тумана и вилоята сервер видит по треку.
  Вкладка «Давомат» — переключатель месяца, сводка за месяц и история дней.
- Отчёты о падениях: ошибки уходят на сервер (`mobile_crash_reports`), без сети и до входа
  ждут в очереди на телефоне.
- Языки: ўзбекча (кирилл, лотин), русский; светлая и тёмная тема.

## Структура `lib/`

- `api/` — HTTP-клиент, модели и методы `/api/mobile/*`.
- `screens/` — вход, оболочка с вкладками (`main_shell`), Бош саҳифа, Ишларим, форма работы,
  Давомат, профиль.
- `services/` — сессия и токены, геопозиция, трек (foreground-сервис), отметка прихода,
  отчёты о падениях, сведения о телефоне.
- `widgets/` (в том числе сценарий «Келдим» — `check_in_flow.dart`), `theme.dart`, `i18n.dart` (строки на трёх языках).

## Сборка

Нужны Flutter SDK и Android SDK (Android Studio). Проверка: `flutter doctor`.

```
powershell -ExecutionPolicy Bypass -File build-apk.ps1 -ApiUrl https://<адрес API>
```

Готовые файлы в корне проекта: `HududNazorati-arm64.apk` — почти все телефоны,
`HududNazorati-arm32.apk` — старые 32-битные (на них arm64 не ставится).

Скрипт принимает только `https://`-адрес, код обфусцируется, карты символов для
разбора отчётов о падениях остаются в `symbols/<версия>` (не в git — хранить вместе с ключом).

### Ключ подписи

Release подписывается только своим ключом. Ключ создан 2026-11-02:
`C:\keys\hudud-nazorati.jks`, пароль — в `C:\keys\hudud-nazorati.key.properties` (копия
`android/key.properties`). Обе вещи хранить с резервной копией вне этого компьютера:
потерянным ключом обновление уже не подписать — приложение придётся удалять и ставить заново
на каждом телефоне. На другой машине сборки — скопировать оба файла туда же.

Как ключ создавался (повторять не нужно):

```
keytool -genkey -v -keystore C:\keys\hudud-nazorati.jks -keyalg RSA -keysize 4096 -validity 10000 -alias hudud
```

Рядом с `android/app` создаётся `android/key.properties` (в git не попадает):

```
storeFile=C:\\keys\\hudud-nazorati.jks
storePassword=<пароль хранилища>
keyAlias=hudud
keyPassword=<пароль ключа>
```

Первая сборка со своим ключом не ставится поверх версии, подписанной отладочным
ключом: старое приложение на телефонах удаляется один раз.

Иконка — знак UNICON SOFT, исходники в `assets/icon`. После их замены:
`dart run flutter_launcher_icons`.

Запуск на телефоне по USB (режим разработчика + отладка по USB):

```
flutter run --dart-define=API_BASE_URL=https://<адрес API>
```

## Падения

Отчёты лежат в таблице `mobile_crash_reports` (версия, `build_number`, телефон, ошибка, стек).
Стек release обфусцирован; расшифровка — картами той же версии:

```
flutter symbolize -i stack.txt -d symbols/<версия>/app.android-arm64.symbols
```

(`app.android-arm.symbols` — для 32-битной сборки; в стеке видно `arch`.)
